## 2026-11-05 — Repo created from the split of `einvoice-platform`

- Why: Mr Bilyaminu asked for the SI and the APP in separate repos (separate ports next). Muhammad chose the "middle way": two independent services plus this small shared NRS toolkit (an external SI would not share our code either; the NRS client and code lists are the one thing both truly need).
- `main` = the merged history of these files, moved with git filter-repo:
  - `shared/src/einvoice_shared/nrs_client.py` → `src/einvoice_nrs/client.py`
  - `shared/src/einvoice_shared/nrs_codes/` → `src/einvoice_nrs/codes/`
  - `fake-nrs/src/fake_nrs/` → `src/einvoice_nrs/fake/` (its `config.json` moved inside, so the installed package finds it)
  - tests → `tests/`; `scripts/fetch_nrs_code_lists.py`, `scripts/nrs_sandbox_probe.py` unchanged.
- `preview`: packaging (`einvoice-nrs`, extra `fake` for the fake NRS), imports renamed, the probe reads Vault itself with hvac (dev-only dependency), CI (ruff, mypy, pytest; no database), README, this log.
- Imports for the services: `einvoice_shared.nrs_client` → `einvoice_nrs.client`, `einvoice_shared.nrs_codes` → `einvoice_nrs.codes`, `fake_nrs` → `einvoice_nrs.fake`. Start the fake NRS with `uv run python -m einvoice_nrs.fake`.
- Muhammad's answers (2026-11-05): the merged history went straight to `main` (one-time); this repo is **public** (no secrets in it); Claude may push release tags.
